# 研究重置与数据契约

## 当前目标

本项目的主问题是：仅使用透析开始时可获得的信息，Shenyi 训练的血流动力学事件模型在有限 Fuding 标注更新后，是否能改善未参与更新的 Fuding 患者会话级低血压和高血压风险识别？

两个并列终点分别是本次透析是否发生 IDH 和透析中高血压，不是精确生存时间。首次检出时间只作为阳性会话的描述性离散时间信息；在两中心测量网格完成协调前，不能作为 Cox 主分析终点。同一会话允许两个终点同时发生。

高血压终点当前固定为“任一透中 MAP 较透前 MAP 上升超过 10 mmHg”。服务器运行会把该规则写入配置和数据审计快照；规则如需修改，必须在正式运行前统一更新构建常量与配置，不能在看到结果后调整。

## 原始数据规则

- 来源：`LongGoodbye/Shenyi-Fuding-original` 的 `updated_dataset_shenyi.csv` 与 `updated_dataset_fuding.csv`。
- IDH：`透前收缩压 - 透中收缩压 >= 30` 或 `透中收缩压 <= 90`。
- IH：`透中 MAP - 透前 MAP > 10`。
- 非 IDH：`idh_event=0`，`idh_time_min=0`；非 IH：`ih_event=0`，`ih_time_min=0`。
- 阳性事件时间为首次满足相应规则的测量节点相对透析开始的分钟数。
- `events`、`event_time_min`、`et_min` 仅作为 IDH 兼容别名。
- 标签使用原始血压；任何裁剪、插补或标准化均不得进入标签路径。
- 血压、舒张压和时间节点数量必须完全一致。时钟跨午夜时按次日处理；不一致或非单调的会话拒绝并记录原因。

## 构建入口

```bash
python src/data_pipeline/HBD_data.py RAW_SHENYI.csv OUTPUT_SHENYI.csv
python src/data_pipeline/HBD_data_fuding.py RAW_FUDING.csv OUTPUT_FUDING.csv
```

每次构建同时写入同名 `.audit.json`，记录输入行数、拒绝原因、患者数和事件数。正式数据再生成前，先人工审阅该审计文件。

## 预测边界

训练特征只能来自 `experiments/audit/feature_allowlist.csv` 中标记为 `allowed=yes` 且 `available_at_prediction_time=start` 的变量。当前会话的透中汇总、事件时间、事件标签和透析结束时长不允许作为预测特征。

历史特征按患者和会话开始时间排序，严格使用更早会话；首个会话的所有历史特征均为零。历史率使用既往会话数作分母，不能按线程完成顺序拼接。

## 实验重启门槛

1. 原始文件 hash 和构建审计文件齐全。
2. 拒绝会话逐项复核，尤其是时间序列错配和跨午夜记录。
3. 全患者历史特征审计通过。
4. 固定患者级 Fuding adaptation/validation/test 拆分。
5. 先建立 source-only 与 local binary baseline，再检验普通目标中心 fine-tuning。
6. 只有在固定测试患者上的配对比较支持增益时，才检验对抗项、KAN 或门控的增量贡献。

现有 Cox/CDAN 结果、时间 AUC、校准和 DCA 工件不满足这份数据契约，只能作为历史探索记录，不能用于投稿或模型选择。

## 新实验入口

默认入口只执行静态审计，不训练：

```bash
python run_all.py
```

只有重建数据的 `binary_data_preflight.json` 为 `passed=true` 且人工确认拆分方案后，才能显式启动：

```bash
python run_all.py --train
```

固定比较为 source-only logistic、local Fuding logistic、source MLP zero-shot 和同一 MLP 的有标签 Fuding 更新。患者拆分使用 `split_seed`，模型初始化使用独立的 `initialization_seed`；多种子只能改变后者。主指标为 ROC AUC、PR AUC 和 Brier score，置信区间与模型差值均按 Fuding 患者聚类 bootstrap。阈值只在相应验证集选择，测试集不参与拟合、调参、早停或阈值选择。
