# 二分类流程审计与训练准备

## 审计结论

项目主流程已从 Cox 生存分析重置为透析开始时的会话级 IDH 二分类风险预测。当前代码已经具备静态审计、患者级固定拆分、三个基线家族、逐例预测和患者聚类 bootstrap 的训练脚本，但当前 `data/processed` 中的历史 CSV 不满足新契约，训练被主动阻断。

本轮未重新生成正式数据，未训练任何模型，也未更新历史性能结果。

## 研究问题

主要问题：在 Fuding 患者完全隔离的测试集中，使用有限 Fuding 标注更新的普通 MLP，是否优于同一 Shenyi source-only MLP 的 zero-shot 预测？

必要比较：

1. Shenyi source-only logistic：检验线性跨中心基线。
2. Fuding local logistic：检验本地有标签线性基线。
3. Shenyi source MLP zero-shot：深度模型更新前基线。
4. 同一 MLP 的 Fuding labeled update：主要候选方法。

KAN、CDAN、门控和 CoxPH 均不属于当前确认性主分析。只有上述基线在固定测试患者上完成并显示仍有未解释增益后，才能逐项作为次要增量实验重新引入。

## 数据流

```mermaid
flowchart LR
    A["HF raw Shenyi/Fuding"] --> B["中心特异序列解析"]
    B --> C["长度与时间单调性验证"]
    C --> D["原始 SBP 计算 IDH 标签"]
    D --> E["严格既往会话历史特征"]
    E --> F["binary_data_preflight"]
    F -->|"通过且人工复核"| G["固定患者级拆分"]
    G --> H["仅 source-train 拟合预处理"]
    H --> I["四个固定比较"]
    I --> J["逐会话预测"]
    J --> K["患者聚类 bootstrap"]
```

标签规则固定为 `透前 SBP - 透中 SBP >= 30` 或 `透中 SBP <= 90`。非事件必须同时满足 `events=0`、`event_time_min=0`、`et_min=0`。标签先于任何裁剪、插补或标准化生成。

## 拆分与预处理

- `split_seed` 只决定患者集合，正式多种子实验不得改变它。
- `initialization_seed` 只决定模型初始化和训练批次顺序。
- Shenyi 按患者拆分 train/validation；source-only 调参与早停只使用这两部分。
- Fuding 先固定 update/test 患者，再在 update 患者中拆 train/validation。
- Fuding test 不参与编码、插补、标准化、调参、早停、阈值选择或校准。
- 类别映射、数值中位数、均值和尺度只在 Shenyi train 拟合并原样应用到所有折。
- 特征必须同时满足 allowlist 的 `allowed=yes` 和 `available_at_prediction_time=start`；结局、当前透中汇总、结束时间和事件时间禁止进入模型。

## 训练输出契约

每次训练写入独立 `experiments/binary_results/binary_<UTC时间>/`，至少包含：

- `config.yaml`：本次冻结配置；
- `data_preflight.json`：训练前数据契约审计快照；
- `split_manifest.json`：各折患者、会话、事件数及患者 ID；
- `preprocessing.json`：source-train 拟合参数和类别映射；
- `test_predictions.csv`：真实 `session_id`、患者 ID、结局和四个模型概率；
- `evaluation.json`：ROC AUC、PR AUC、Brier、患者 bootstrap CI 和配对 AUC 差值；
- `logistic_models.pkl`、`mlp_models.pt`：可复核模型工件。

主结论只看 `updated_mlp_vs_source_mlp` 的固定测试患者配对结果。`updated_mlp_vs_local_logistic` 用于判断深度模型是否提供超越本地线性更新的增益。置信区间跨零时不能写优于。
