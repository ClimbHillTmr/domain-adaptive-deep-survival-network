修复：

1. 从 Hugging Face 或原始备份恢复 processed/raw 数据。
2. 重新生成 final CSV。
3. 为两个 final CSV 写入 hash、行数、列数、患者数、事件数审计文件。

验收：

- file path
- sha256
- n_rows
- n_cols
- n_patients
- n_events

### P0-3 预测时点不清，疑似未来信息进入模型

证据：

- `src/data_pipeline/HBD_data.py:386-409` 保留 `透析中收缩压_mean/std`、`透析中舒张压_mean/std`、`透析中脉搏_mean/std`、`动脉压_mean/std`、`血流速_mean/std`、`跨膜压_mean/std` 等透析中全程统计。
- `src/data_pipeline/HBD_data.py:643-679` 历史均值候选列也包含透析中全程统计。
- 当前 `src/data/dataset.py:7-20` 主特征列表未直接包含这些原始透析中全程统计，但会动态追加所有 `history_` 前缀列，历史率/历史分布仍需审计。

影响：

- 如果研究目标是透析开始前预测，则当前 base table 包含治疗过程/结局生成同期信息，必须严格排除。
- 如果目标是透析过程中动态预测，则必须明确预测时间点和允许使用的观测窗口。

修复：

1. 冻结预测时点：推荐设为“透析开始前/透析开始时”。
2. 建立 allowlist，而不是从 final CSV 动态扫列。
3. 禁止使用当前 session 的任何透析中全程统计和事件衍生列。
4. 历史特征只允许 prior sessions 的历史聚合。

验收：

生成 `experiments/audit/feature_allowlist.csv`：

- feature
- category
- available_at_prediction_time
- source_column
- allowed yes/no
- reason

### P0-4 历史特征需要重新生成并审计

- 第一条 session 历史特征全为 0。

证据：

- `src/evaluate/metrics.py:49-71` 按 session bootstrap。

验收：

`evaluation_results.json` 包含：
